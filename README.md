# cfsm-widget

[CF-Server-Monitor](https://github.com/huilang-me/CF-Server-Monitor) 探针面板的 **iOS 主屏小组件**，
支持 **Egern** 和 **Scriptable**。两边跑的是同一份代码，显示内容和配置项完全一样，装哪个都行。
配色与指标口径沿用面板主题 [CFSM-Theme-LuminaPlus](https://github.com/volcano-1025/CFSM-Theme-LuminaPlus)。

| 尺寸 | 内容 |
| --- | --- |
| **小** | 单台机器：旗帜 + 名称 + 在线点 + 更新时间、CPU / 内存 / 磁盘三条进度条、延迟与丢包、实时上下行 |
| **中** | 汇总条（在线数、离线数、全站实时速率）+ 5 行节点（CPU、内存、延迟、丢包） |
| **大** | 标题 + 三块汇总（在线数 / 实时速率 / 累计流量）+ 9 行节点（多一列磁盘）+ 离线名单 |

点按小组件会打开面板：小尺寸进那台机器的详情页，中 / 大尺寸进首页。

## 安装 · Egern

### 第 1 步：创建脚本

**工具** → **脚本** → 点 **+**：

| 字段 | 填写内容 |
| --- | --- |
| 名称 | `cfsm-status` |
| 类型 | 选 **通用** |
| 文件位置 | 选 **远程**，填下面那条链接 |
| 环境变量 | `API_BASE` = 你的面板地址 |

```
https://raw.githubusercontent.com/volcano-1025/cfsm-widget/main/cfsm-status.js
```

`API_BASE` **只写 origin** —— `https://status.example.com` 这样，不要带结尾斜杠，
也不要带 `/admin` 之类的路径。填错最直接的表现就是卡片上写「返回的不是 JSON」。

### 第 2 步：创建小组件

**分析** 标签页 → 点左上角按钮进入 **小组件画廊** → 点 **+**：

| 字段 | 填写内容 |
| --- | --- |
| 名称 | `服务器状态`（随便起，这是待会在主屏上要选的名字） |
| 脚本名称 | 选第 1 步创建的 `cfsm-status` |

保存后小组件会出现在画廊里并自动运行 —— **在画廊里就能直接看到渲染结果**，不用先加到主屏。

### 第 3 步：加到主屏

1. 长按主屏幕空白处，点击左上角 **+**
2. 搜索 **Egern**，选择小组件尺寸（小 / 中 / 大都支持）
3. 添加后长按小组件 → **编辑小组件** → 选择「服务器状态」

第 3 小步最容易漏：Egern 在主屏上只是一个壳，**不选具体哪个小组件就是一片空白**。

想固定看某台机器、换线路，见[配置](#配置)。

### 更新

远程脚本按 `update_interval`（默认 86400 秒，一天）自动重新拉取。想马上拿到新版本，
去 **工具** → **脚本** 里对它手动更新一次。

<details>
<summary>也可以直接写配置文件（效果完全一样）</summary>

习惯改 YAML 的话，第 1、2 步等价于：

```yaml
scriptings:
  - generic:
      name: cfsm-status
      script_url: https://raw.githubusercontent.com/volcano-1025/cfsm-widget/main/cfsm-status.js
      env:
        API_BASE: "https://status.example.com"

widgets:
  - name: 服务器状态
    script_name: cfsm-status
```

配置里已经有 `scriptings:` 或 `widgets:` 的话，**只把 `-` 开头的条目并进已有的那一段**，
别把顶层字段名再写一遍 —— YAML 里同一个键出现两次，后面那个会把前面整段顶掉。

</details>

## 安装 · Scriptable

### 第 1 步：新建脚本

1. 打开 Scriptable，点右上角 **+** 新建一个脚本
2. 用手机浏览器打开下面这条链接，**全选复制**，粘进刚建的脚本里：

   ```
   https://raw.githubusercontent.com/volcano-1025/cfsm-widget/main/scriptable/loader.js
   ```

3. 把开头 `CONFIG` 里的 `API_BASE` 改成你的面板地址（只写 origin，规则同上）
4. 点顶部的脚本名改成 `CFSM`（随便起，第 3 步要选），点 **Done**

粘进去的只是一段 50 多行的加载器。真正的代码由它从本仓库下载、缓存在手机上，
所以**以后更新不用重新粘**。

### 第 2 步：在 App 里运行一次

点右下角 ▶︎ 运行，选一个尺寸预览。这一步顺带把代码下载下来，看到正常的卡片再去加主屏。

### 第 3 步：加到主屏

1. 长按主屏幕空白处，点击左上角 **+**，搜索 **Scriptable**，选尺寸后添加
2. 长按这个小组件 → **编辑小组件**
3. **Script** 选 `CFSM`；**Parameter** 按需填，写法见[配置](#配置)，不填就用 `CONFIG` 里的

**When Interacting** 不用改，脚本自己设了点按跳转的地址。

### 更新

加载器缓存的代码**一天更新一次**。想马上拿到新版本，在 Scriptable 里**手动运行一次**这个脚本
（App 里运行总会重新下载）。下载失败时继续用上次的缓存，不会变成报错卡片。

加载器本身（粘进去的那一段）不会自动更新；它几乎不用改，真改了会在这里写明。

## 配置

### 填在哪

两个 App 都分「共用」和「单个小组件」两层，后者覆盖前者：

| | 所有小组件共用 | 只管这一个小组件 |
| --- | --- | --- |
| **Egern** | 脚本的环境变量 | 小组件的环境变量 |
| **Scriptable** | 加载器顶部的 `CONFIG` | 编辑小组件 → **Parameter** |

一般把 `API_BASE`、`CARRIER` 放共用层只填一次，`NODE`、`TITLE`、`ROWS` 这类每块不同的放小组件上。

Scriptable 的 Parameter 只有一行，写法是 `KEY=值`，多条用**分号**隔开
（不能用逗号 —— `NODES` 自己就是逗号分隔的）。key 不分大小写；中文输入法打出的全角 `；`、`＝`
和中文引号也认。

| 想要 | Parameter 填 |
| --- | --- |
| 小尺寸固定看某台 | `NODE=hk-01`，或者直接写 `hk-01` |
| 再指定线路 | `NODE=hk-01; CARRIER=电信` |
| 中尺寸只看某个分组 | `GROUP=亚洲` |
| 中 / 大尺寸固定列表 | `NODES=hk-01,jp-tokyo,us-la` |
| `CONFIG` 里没填地址 | `https://status.example.com; hk-01`（网址开头的一段自动当 `API_BASE`） |

### 全部配置项

| key | 默认 | 说明 |
| --- | --- | --- |
| `API_BASE` | **必填** | 面板地址，只写 origin，不带路径与结尾斜杠。例 `https://status.example.com` |
| `NODE` | 空 | 小尺寸显示哪台机器。三级匹配：id 全等 → 名称全等（忽略大小写）→ 名称包含。留空则取排序里的第一台 |
| `NODES` | 空 | 中 / 大尺寸固定显示哪几台，逗号分隔，按写的顺序排。匹配规则同 `NODE`，写错的会被跳过 |
| `GROUP` | 空 | 没写 `NODES` 时，只看某个分组（后台的「服务器分组」） |
| `SORT` | `order` | 没写 `NODES` 时的排序。`order` 跟随后台的「服务器排序」；`health` 改成离线优先、其次 CPU 从高到低 |
| `TITLE` | `服务器状态` | 大尺寸左上角标题 |
| `CARRIER` | `auto` | 延迟与丢包看哪条线路：`ct`/`电信`、`cu`/`联通`、`cm`/`移动`、`bd`。`auto` 在三网里取延迟最低的一条 |
| `LOSS_WINDOW` | `hour` | 丢包的口径：`hour` 最近一小时的均值，`now` 最后一次探测的瞬时值 |
| `FLAG` | `emoji` | 机器名前的地区标记：`emoji` 旗帜，`code` 换成「HK」这样的文字，`none` 不显示 |
| `BACKGROUND` | `system` | 背景：`system` iOS 小组件的标准底色，`glass` 一层灰色渐变，`solid` 面板主题的底色，`clear` 全透明（实际透不出壁纸） |
| `LATENCY_STYLE` | `text` | 延迟数值的画法：`text` 数字染成延迟色；`chip` 延迟色当底、数字用正文色（更清楚但更花） |
| `ROWS` | 中 5 / 大 9 | 列表最多显示几行 |
| `REFRESH` | `1` | 期望的刷新间隔（分钟）。iOS 有刷新预算，实际间隔通常被系统拉长，写小了也不会更快 |
| `DEBUG` | 空 | 填 `1` 时只显示一段排查文字，见[装不上？按现象对](#装不上按现象对) |

没写 `NODES` 时列表**跟随后台的服务器排序**（`sort_order`）；后台没排过序（全是 0）就保持后端
下发的顺序。后台设为隐藏的机器一律不显示。小尺寸没写 `NODE` 时取的也是这个排序里的第一台。

`CARRIER` 点名某条线路后就只认那一条，那条没数据就显示 `—`，不会偷偷回退到别条 ——
写着「电信」却显示联通的数才是真的误导。小尺寸会把线路名标在延迟左边，大尺寸标在标题栏图例的末尾。

## 装不上？按现象对

先看**预览**里那一块渲染成什么样：Egern 看**小组件画廊**，Scriptable 在 App 里**运行一次**。
预览就是真机的渲染结果，失败原因会直接写在卡片上：

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 未配置 API_BASE | 配置没读到 | 检查 `API_BASE` 的拼写（全大写），以及填在了哪一层 |
| 无法连接 xxx | 域名不通或超时 | 用手机浏览器开一下 `https://你的地址/api/servers`，确认能出 JSON |
| 返回的不是 JSON | `API_BASE` 写错了 | 只写 origin，不要带 `/` 结尾、不要带 `/admin` 之类的路径 |
| 站点未公开 | 后台关了公开访问 | 小组件不支持，见[限制](#限制) |
| 站点已开启人机验证 | 后台开了全局 Turnstile | 小组件不支持，见[限制](#限制) |
| 未找到节点 xxx | `NODE` 没匹配上 | 填后台里的机器 id，或名称的一段（不区分大小写） |
| 最后一行缺一截 | 机型比参考尺寸矮 | 把 `ROWS` 调小一档 |
| Egern：主屏一片空白，画廊里是好的 | 主屏上的 Egern 壳没绑定具体小组件 | 长按小组件 → **编辑小组件** → 选「服务器状态」 |
| Egern：画廊的 **+** 里选不到脚本 | 脚本没建成，或类型没选 **通用** | 回 **工具** → **脚本** 检查名称与类型 |
| Scriptable：红字「CFSM 小组件加载失败」 | 第一次下载代码就没成功（还没有缓存可用） | 确认手机能打开 raw.githubusercontent.com，然后在 App 里运行一次 |
| Scriptable：Parameter 填了不生效 | 用了逗号分隔多条，或 key 拼错 | 多条之间用分号；key 照[全部配置项](#全部配置项)写 |

还是定位不了，给那个小组件加一条 `DEBUG` = `1`：卡片会改成一段纯文本，列出尺寸、面板域名、
拿到几台机器、一小时丢包窗口拿到几格。**能出文字**说明取数和渲染都通、问题在版式；
**还是空白**说明脚本压根没跑起来，回安装步骤检查。「窗口 0 格」说明面板后端版本太低，
丢包会回落到瞬时值。

## 限制

- **只支持公开站点。** 站点如果关掉了公开访问，或在后台开了全局 Turnstile 人机验证，
  小组件拿不到数据（那份验证凭证只能在浏览器里解人机验证才能拿到，脚本没法绕）。
  这两种情况小组件会直接把原因写在卡片上。
- **只支持单个后端。** 多站部署请为每个后端各建一个小组件。
- **行数超了会被裁掉，不会压缩。** 每一行都是定高的（不定高的话 Mac / iPad 上行间会被扯出大片空隙），
  默认行数按 iPhone 14 Pro 那档留了余量。你的机型看到最后一行缺一截，把 `ROWS` 调小一档。
- **丢包默认是最近一小时的均值**，所以经常和面板上的瞬时值对不上：一次抖动能让瞬时值跳到
  100% 再跳回 0%，一小时均值不会。
  - 数据来自 `/api/servers` 里自带的一小时探测窗口（30 格、每 2 分钟一格），**不多发任何请求**。
    这是面板后端 **Workers 2.8.3 Beta2** 起才有的字段，版本更低时自动回落到瞬时值。
  - 没探测到的格子不算进分母，免得把丢包率冲淡；后端为凑满 30 格复制出来的格子
    （连续 4 格以上完全相同）整段丢掉。
- 线路的探测目标由后台配置，公开接口不下发，小组件也就无从显示。
- 每次刷新只发一个请求 `GET {API_BASE}/api/servers`，不碰历史接口 —— 逐节点查历史会让后端
  D1 读行翻几十倍。

## 开发

```bash
npm install
npm test        # 纯函数 + DSL 结构校验 + Scriptable 整条链
npm run lint
npm run preview # 生成 preview-{small,medium,large,errors}.html
```

| 文件 | 作用 |
| --- | --- |
| `cfsm-status.js` | 核心脚本：取数、排序、三个尺寸的版式，返回 Egern 的 Widget DSL。Egern 直接远程加载它 |
| `scriptable/loader.js` | 用户粘进 Scriptable 的加载器，只负责下载、缓存、执行另外两个文件 |
| `scriptable/runtime.js` | 拼出 Egern 风格的 `ctx`，执行核心脚本，把 DSL 翻成 Scriptable 的 `ListWidget` |
| `tools/preview.mjs` | 把 DSL 翻成等尺寸 HTML，浅深色各一份，在本机调版式用 |
| `test/dsl-schema.js` | Egern DSL 的属性白名单，逐条抄自[官方文档](https://egernapp.com/zh-CN/docs/configuration/widgets/) |

改版式、改口径只改 `cfsm-status.js`，两个 App 一起生效。它必须保持**单文件、无依赖**
（两边都没有打包步骤），具名导出只给测试用。

`npm run preview` 是**近似预览**，不是模拟器：字体度量与 WidgetKit 不同，自动缩字也模拟不了，
只用来抓「名字被挤断、某列没对齐、某块被压成 0 宽、深色下看不清」这类结构问题。

两份测试兜着最难查的那类错误 —— 写错了不报错、真机上只表现为「样式没生效」：
DSL 白名单拦住写错的键名；`test/scriptable.test.js` 用假的 Scriptable API 把「加载器 → 运行时 →
核心脚本」整条链跑通，并检查核心脚本用到的每个 DSL 属性运行时都翻译了。

改代码前先看 [CLAUDE.md](CLAUDE.md)：踩过的真机坑（行必须定高、小尺寸的行结构、
image 不收远程 URL、透明外观只保留透明度）都记在那里，预览里全都看不出来。
